Product build

Contract Clause Extraction and Review

A first-pass clause table for a whole batch of contracts. Every finding shows the exact contract wording, and every gap is flagged for a human to check.

Kerrian Gordon & Mara Munoz

The problem

Reviewing contracts is repetitive, and a missed clause is costly

What reviewers are asked to do

  • Move commercial contracts quickly
  • Track renewal dates
  • Escalate non-standard language to a senior lawyer

Where we think the time goes

  • Finding the same clause types in every agreement
  • Copying quotes, document names and pages into a table
  • Not knowing if an empty keyword search means the clause is absent

These time sinks are our hypotheses. No job posting proves them yet.

Who it's for

Reviewers who turn a batch of contracts into a table

Primary users

Junior corporate associates, paralegals and legal analysts. They care about not missing a clause and showing where each finding came from.

Secondary users

Senior lawyers. They check the table and decide what each provision means for the deal.

Later audiences

Contract managers, in-house counsel, procurement and legal operations.

Example: Maya, a junior associate

Before an acquisition closes, she must review 30 customer and supplier contracts and report which ones contain assignment restrictions or change-of-control terms. (An illustrative persona, not a documented customer.)

Building for a job description

We read each posting twice: what it says, and what it reveals

The method

  • Says: the duties the posting lists outright
  • Reveals: the daily reality behind them
  • Signals: words like each, every, track, review, escalate point to repeated manual work

The four checks, applied to our build

  • Specific: yes. Named roles, defined task
  • Research-able: partly. Real postings and a public labeled dataset
  • Repetitive: probably. Same checklist on every contract
  • Multi-step: yes. Read, find, verify, review, export

Reviewers spend their time on what the terms mean, not on searching and copying.

What sets it apart

Two guarantees, built in

100%

Verbatim quotations

A quote is shown only if it appears word for word in the contract. Anything the model paraphrases is dropped.

100%

Visible gaps

A category with no result is never left blank. It says "not found, review required", so an empty search is never mistaken for an absent clause.

Every category in every contract ends in one of three states

Found

A verified quote waits for review.

Not found, review required

The tool never claims the clause is absent.

Failed to process

Unreadable or scanned file. Listed with the reason.

How it works

Six stages, and the fourth protects the reviewer

1IngestRead each PDF page and record where pages start
2ChunkSplit into ~3,000-character windows with overlap
3ExtractA regex pass, then one model call per chunk
4VerifyKeep a quote only if it's in the contract word for word
5StoreFindings and statuses go to SQLite
6ExportReviewed table to CSV

Locations are PDF page numbers. Model answers are cached, so re-runs don't pay twice.

Scope

A small, finished loop beats a large unfinished one

Must have (P0)

  • Upload multiple contracts
  • See which files failed, and why
  • Choose categories
  • Quote and page for every finding
  • Status per category
  • Accept or remove
  • CSV export

If time allows

  • Highlight the quote in the full text
  • Flag a question for a senior lawyer
  • Add a passage the tool missed
  • Filters and custom categories

Not doing

  • Legal interpretation or risk scores
  • OCR for scanned PDFs
  • Drafting and redlining
  • Accounts and integrations

Risks

What could go wrong, and what we do about it

Messy PDFs

Scanned files fail clearly. Quotes that don't match are dropped, so the category reads "not found, review required" instead of a wrong quote.

Long contracts

Parallel calls and caching. The 30-minute target is tested, not promised for the demo.

Cost and speed

Not measured yet. A budget cap stops a run, and we measure 3 contracts first.

Model fails during the demo

Replay from the cache of an earlier run. The mock provider is the last resort, labeled as a mock.
